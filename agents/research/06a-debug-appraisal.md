# Debug Research — Adversarial Appraisal

**Evidence mechanisms** enumerates what actually stops an agent confabulating a root cause. The appraiser also ruled on whether a numeric confidence score is meaningful given LLM calibration research — it is not, which is why the agent grades on an evidence ladder instead.

## Verdicts

- **Demanding a demonstrated causal link before calling a diagnosis proven: disable/remove the suspected cause and the symptom disappears; restore it and the symptom returns**
  - *Verdict:* battle-tested
  - *Reasoning:* This is the strongest available lever and I want to say so plainly. Its support is definitional and convergent rather than benchmarked: Zeller & Hildebrandt's 1-minimality (IEEE TSE 2002, peer-reviewed, 90%+ input reductions on real Mozilla/GCC failures) IS this test mechanized at input granularity; git bisect is it mechanized over history; Agans Rule 9 is it stated for humans; harness-debugging, prp-debug (necessity/sufficiency triad) and CockroachDB all independently require some form of it. The decisive property is not that it was measured against a control arm — it is that a both-directions result is the only claim in a diagnosis an LLM cannot produce from priors. Every other artifact (a stack trace, a metric chart, a plausible chain) can be narrated; a toggle-off/toggle-on observation must be produced by the environment. Honest caveat: I found no study that A/B tests this as a prompt mechanism, and it is unavailable for a large fraction of production incidents (non-reproducible, one-shot, mitigated-before-captured). That makes it the top of the confidence ladder, not the entry requirement.
  - *Adopt:* adopt
- **Reproduction attempted before any hypothesis is formed, with a defined failure branch that caps confidence when it fails**
  - *Verdict:* battle-tested
  - *Reasoning:* Convergent across independent lines: SWT-Bench (NeurIPS 2024, peer-reviewed) reports generated reproduction tests roughly doubled SWE-Agent patch precision; Anthropic's own scored SWE-bench Lite config makes 'create a script to reproduce the error and execute it to confirm the error' step 2 of 5; harness-debugging, investigator.md and prp-debug independently make it a gate. IMPORTANT CORRECTION to the dossier: the headline +52-point figure comes from ORACLE-SWE, which I checked directly — arXiv 2604.07789 exists but is explicitly still under peer review (submitted Apr 2026, revised May 2026), so the dossier's 'peer-reviewed-or-benchmarked' label is wrong. It is a single unreplicated preprint, and its signals are oracle upper bounds extracted from gold patches, which cannot be obtained in the wild. The principle survives on convergence without that number; do not build the prompt's justification on it.
  - *Adopt:* adopt
- **Treating an LLM-written reproduction test as evidence the bug is understood, or as a correctness oracle**
  - *Verdict:* contradicted-by-evidence
  - *Reasoning:* Agentless measured this directly: of 300 SWE-bench Lite issues, 213 generated tests emitted the 'issue reproduced' message against the broken repo, but only 94 correctly emitted 'issues resolved' after the ground-truth patch was applied. Roughly 56% of tests that look like reproductions do not actually validate the fix — they fail for a reason unrelated to the reported bug. A reproduction proves a symptom is producible; it does not prove it is THE symptom. Adapt by requiring the repro to assert on the specific reported failure signature, and by adopting SWE-agent's sentinel trick (print a completion line) so silence is never read as success.
  - *Adopt:* adapt
- **A numeric self-reported confidence score (percentage, 0-1, or per-hypothesis probability) attached to the diagnosis**
  - *Verdict:* contradicted-by-evidence
  - *Reasoning:* I verified the ICSE 2025 calibration paper text directly. Verbatim: intrinsic confidences show ECE 'ranging from 0.09 to 0.73, suggesting intrinsic LLM confidences are poor predictors of code correctness'; and among line completions with average probability 'greater than 90%, only 52% actually passed test cases', with one buggy completion carrying 'an average per-token confidence of 91%'. Verbalized/reflective self-rating is measured as 'rather inconsistent'. Post-hoc Platt scaling improves calibration but requires prior correctness labels, which a live investigation does not have. A number that is uncorrelated with correctness but rendered in the syntax of precision is worse than no number: it converts a wrong diagnosis into an actionable-looking one. Reject model-generated confidence percentages outright.
  - *Adopt:* reject
- **Cross-run agreement across N independent investigations, reported as the confidence quantity instead of a self-assessed score**
  - *Verdict:* battle-tested
  - *Reasoning:* The only calibration signal in this entire corpus with a measured correlation to correctness, and I verified the table directly in the AutoFL PDF: Spearman +0.57 (Precision@1), +0.67 (Reciprocal Rank), +0.70 (Average Precision) on Defects4J and +0.52/+0.50/+0.49 on BugsInPy, all p<0.0001, over 798 bugs, with 5 reruns. Also verified: only ~20% of individual explanations were accurate, yet 56.7% of bugs had at least one accurate explanation somewhere in the ensemble — so single-shot answering discards information that is demonstrably present. Two adaptations required. First, 0.49-0.70 is a moderate ranking signal, not a calibrated probability: report 'named by 3 of 3 runs', never 'therefore 90% likely'. Second, AutoFL's runs varied the failing test where several existed — that is closer to independent evidence than to temperature resampling, so give each run a genuinely different entry point rather than re-rolling the same prompt.
  - *Adopt:* adopt
- **A reflection or self-critique pass ('now check your own diagnosis') with no new evidence gathered between passes**
  - *Verdict:* contradicted-by-evidence
  - *Reasoning:* Huang et al. (ICLR 2024) find intrinsic self-correction without external feedback frequently degrades performance, and the ICSE 2025 calibration study independently finds reflective confidence methods 'rather inconsistent'. Mechanistically the failure is predictable: with no new observation, a second pass can only re-weight the same context, and the dominant effect is converting a hedged answer into a confidently defended one. Reject self-critique. Replace it with re-entry that carries new evidence — an additional query, a probe, or an independent run with a different starting point.
  - *Adopt:* reject
- **Grounding every assertion in a tool call (ReAct-style investigation over real telemetry) in order to improve diagnostic correctness**
  - *Verdict:* contradicted-by-evidence
  - *Reasoning:* This needs splitting, and the split is the single most decision-relevant finding in the corpus. As a CORRECTNESS intervention it is contradicted: Microsoft's RCA agent study on real cloud incidents measured ReAct at 35% versus a plain retrieval baseline at 39% and CoT at 39% — flat to slightly worse. As a HALLUCINATION intervention it is strongly supported: hallucination within correct predictions fell to under 1% (ReAct) versus 26% (retrieval baseline), and within incorrect predictions 6% versus 49%; the grounded agent also declared 'Insufficient Evidence' in 66% of its wrong answers. So tools do not make the agent right — they make it stop inventing, and make it aware when it lacks grounds. Adopt for exactly that reason, and never sell tool access as an accuracy mechanism.
  - *Adopt:* adopt
- **'Insufficient evidence / inconclusive' as a first-class, counted value in the output schema with a required reason**
  - *Verdict:* battle-tested
  - *Reasoning:* Rare case of a prompt-level mechanism with a direct behavioral measurement: the Microsoft grounded agent emitted 'Insufficient Evidence' in 66% of its incorrect predictions, meaning most of the time it was wrong it had already flagged that it lacked grounds — that is the abstention channel doing real work rather than aspiring to. Independently converged on by GitLens (counts inconclusive investigations in the report header; enum includes Cannot Reproduce from Description, Insufficient Information, Likely Fixed), CockroachDB (inconclusive branch terminates in a specific debug.zip command), and Zeller's UNRESOLVED as a formal third outcome. Critical corollary: if the output schema has no shape for 'undetermined', the agent fills the root-cause field regardless — so this is a schema requirement, not a tone instruction.
  - *Adopt:* adopt
- **Provenance tagging of each claim as observed-in-tool-output / retrieved-from-existing-writeup / inferred, with retrieved claims capped below proven**
  - *Verdict:* battle-tested
  - *Reasoning:* The failure it targets is heavily measured even though the mechanism itself is not. SWE-Bench+ found 32.67% of successful patches had the solution stated directly in the issue report or comments and a further 31.08% passed only through weak tests, dropping SWE-Agent+GPT-4 from 12.47% to 3.97% once filtered. SWE-Bench Illusion found buggy-file identification from issue text alone at 76% on benchmark repos versus 53% on non-benchmark repos. Cursor's sealed-environment study found 63% of one frontier model's successes retrieved the fix rather than derived it, with 7.5-20.7 point drops once git history and network were sealed. In a live incident there is no upstream PR to find, so an untagged retrieved answer is a capability the agent appears to have precisely when it does not. GitLens's Source Attribution field is the cleanest implementation I found.
  - *Adopt:* adopt
- **Scoping investigation to the files and frames named in the stack trace or error group**
  - *Verdict:* contradicted-by-evidence
  - *Reasoning:* AutoFL's difficulty categorization (which I confirmed exists in the paper, with the ANOVA on call-chain length by category) partitions bugs by whether a faulty method is called by the failing test and/or appears in the stack trace, and a large plurality of Defects4J bugs fall in the (False, False) cell — faulty method neither in the trace nor directly called. The dossier's precise figure (~23.5% in-trace) comes from a figure I could not read from the extracted text, so treat the exact percentage as unverified while the direction is solid and the paper is explicit that these are the 'hardest' bugs. Sentry's own errors concept doc independently warns the crash you are looking at can be a downstream symptom of a different issue on the same trace. Replace with backward tracing to the point of value divergence.
  - *Adopt:* reject
- **Ranking suspects by what is unique to the failing run (log diffing, spectrum-style suspiciousness, release comparison, 'only errors have this attribute')**
  - *Verdict:* contradicted-by-evidence
  - *Reasoning:* FALCON (ICSE 2025) supplies the decisive counterexample from real industrial logs: the faulty method appears in BOTH passing and failing logs while its downstream callee appears only in the failing log, so every one of 34 spectrum-based formulas ranks the innocent downstream method first. This is the systematic failure of every difference-based ranking, and it is exactly the instinct an agent applies to PostHog breakdowns, Sentry release comparisons and log diffs. It produces plausible, evidence-backed, wrong answers — the precise class this design must avoid. Adapt rather than reject: keep the diff as a hypothesis generator, but require the agent to explicitly test the alternative that the culprit is present in both populations and merely behaving differently.
  - *Adopt:* adapt
- **Over-representation / negative-control test: re-run the breakdown against the unaffected or overall population before calling a dimension implicated**
  - *Verdict:* battle-tested
  - *Reasoning:* Verified verbatim on disk in PostHog's APM skill: 'A value at 95% of errors but 10% of traffic is the culprit; one at 95% of both is just volume.' Independently automated by Honeycomb's BubbleUp (dimension distribution of the anomalous region versus baseline), independently required by PostHog's flag skill (compare variant split among errors to the project's overall exposure on the same flag in the same window), and it is the software instance of pretest probability from differential diagnosis. It is also mathematically sound rather than heuristic — it is base-rate correction, and one extra query defeats the highest-frequency wrong-diagnosis generator in metrics-driven investigation ('93% of errors are on Chrome' when Chrome is 90% of traffic).
  - *Adopt:* adopt
- **Temporal correlation with a deploy, config push or flag flip treated as the cause**
  - *Verdict:* contradicted-by-evidence
  - *Reasoning:* 'What changed' is correctly the highest-prior question, and it is also the most seductive wrong answer, cheaply available from every observability tool. Google SRE names mistaking correlation for causation on 'spurious coincidences in complex systems' as a listed pitfall. Two independent vendors ship the specific refutation: PostHog's deploy-timing skill, verified verbatim on disk, states 'A later date_marker is necessary but not sufficient — a deploy can fire just after the merge yet build a slightly older commit', with the exact gh api compare check requiring behind_by:0; CockroachDB independently requires searching for operation-confirmation logs to 'verify the operation actually caused the finding'. Adapt: keep the question first, but require a confirmation artifact before the correlation may be promoted above 'correlational'.
  - *Adopt:* adapt
- **Narrowing the candidate set with cheap non-LLM signal first (structural graphs, classical FL, error grouping, query insights), then spending model tokens on verification rather than search**
  - *Verdict:* battle-tested
  - *Reasoning:* Three independent measured results in the same direction, improving accuracy, latency and cost simultaneously. LocAgent: dependency-graph traversal reaches 92.7% file-level localization and +12% Pass@10 issue resolution, with a fine-tuned 32B model matching proprietary SOTA at ~86% lower cost. MemFL: +12.7% on Defects4J (+27.6% on complex projects) at 17.4s/bug (-79% time) and $0.0033/bug (-67% cost). FlexFL: classical FL narrows first, and with only Llama3-8B it locates 42 more bugs than AutoFL and 63 more than AgentFL, both of which used GPT-3.5. Agentless's combined prompt+embedding file retrieval (81.67%) beats either alone. The generalization is that the model's job is verification, not search.
  - *Adopt:* adopt
- **Bulk context: pasting whole files, full execution traces, raw log dumps or complete query result sets into the model**
  - *Verdict:* contradicted-by-evidence
  - *Reasoning:* One of the few places where more information measurably makes the model worse at higher cost. Agentless: complete-file input scored 53.67% correct at $0.15 per issue versus a skeleton (signatures and structure only) at 58.33% for $0.02 — better accuracy at one seventh the cost. The execution-trace study found naive trace injection helped in only 2 of 6 dataset/model configurations, with benefit decreasing as trace complexity increased. Convergent engineering response across vendors: OpenRCA's RCA-agent writes Python to aggregate rather than reading telemetry (verified verbatim in the repo README: 'By using Python for data retrieval and analysis, the model avoids processing overly long contexts'); Grafana ships get_dashboard_summary specifically to reduce tokens; Rootly ships a ~70-tool slim profile. Reject bulk; adopt curated, skeletal, aggregated evidence.
  - *Adopt:* reject
- **Interactive debugger access (pdb / DAP-over-MCP) granted to the agent from step zero**
  - *Verdict:* contradicted-by-evidence
  - *Reasoning:* debug-gym is the clean controlled experiment and it contradicts the default-on design. On the simple Aider benchmark immediate debugger access hurt nearly every model (GPT-4o 76.4 to 69.7; o1-preview 90.5 to 89.0), and on SWE-bench-Lite it was net negative for GPT-4o (19.1 to 17.2) and 4o-mini. The measured-best variant is deferred unlock — debugger available only after 5 failed rewrite attempts — which the authors report outperformed the plain agent in all SWE-bench-Lite cases, and strong models gained substantially (Claude 3.7: 37.2 to 48.4 to 52.1). I verified the paper exists and its framing but could not confirm the per-model table from the abstract alone. Two further constraints: the authors attribute weak-model failure to issuing debugger commands 'without a clear strategy', and the DAP-over-MCP ecosystem is immature (repos in the 5-97 star range, several self-labelled experimental), so availability must never be assumed.
  - *Adopt:* adapt
- **Ranked competing hypotheses with a falsifier pre-committed before evidence gathering (ACH)**
  - *Verdict:* plausible-unproven
  - *Reasoning:* No measurement exists for LLM diagnosis — no A/B against single-hypothesis investigation anywhere in this corpus. Support is convergent design (wshobson's parallel-debugging, CockroachDB, GitLens, harness-debugging, investigator.md all independently arrive at it) plus a measured analogue in a different field: premature closure and anchoring are the identified top cognitive causes of diagnostic error in medicine, where diagnostic error was 17% of preventable errors in the Harvard Medical Practice Study. The mechanism is also structurally sound in a way that resists the LLM failure mode: a falsifier written after evidence gathering is chosen to be one that happens not to have been met, so the ordering constraint is doing the work. Adopt with clear eyes that its efficacy here is inferred, and keep the hypothesis count small (2-3) since each carries token cost with no measured return.
  - *Adopt:* adapt
- **Parallel single-hypothesis subagents in isolated contexts with a separate arbiter**
  - *Verdict:* plausible-unproven
  - *Reasoning:* The isolation half has indirect measured support — AutoFL's benefit comes precisely from independent runs whose union contains an accurate explanation for 56.7% of bugs against 20% per run. The one-hypothesis-per-agent half has none, and the arbitration protocol has none. Real costs: N-times token spend, and an investigator forbidden from pivoting will burn its full budget on a hypothesis that died in its first two tool calls. Adapt into the cheap version: run N independent passes over the same question with different entry points and compare, rather than assigning each agent a fixed hypothesis it may not abandon.
  - *Adopt:* adapt
- **Enforcing diagnose-don't-fix through the tool allowlist (no Edit/Write) rather than through prose instruction**
  - *Verdict:* plausible-unproven
  - *Reasoning:* No measurement, but the reasoning is sound and the convergence is real (investigator.md, team-debugger, harness-debugging's read-only phase, PostHog's 'Don't propose a fix in the synthesis unless the cause is obvious' which I verified on disk, Sentry's 'state the root cause before touching code'). Two distinct benefits: a prose constraint competes with strong helpfulness priors at exactly the moment the agent believes it knows the answer, whereas an allowlist does not; and once a fix is written the agent is invested in the hypothesis that motivated it, so every subsequent observation is read as confirmation. It also converts the practitioner-reported observability write hazard (agents silencing real alerts, re-triggering failed deploys during outages) into a structural impossibility. Cheap, and the failure mode it prevents is severe.
  - *Adopt:* adopt
- **Symptom-shape to next-probe routing tables (PostHog sparkline shapes, CockroachDB's 25-row finding-to-metrics table, Grafana Sift's eight named checks)**
  - *Verdict:* plausible-unproven
  - *Reasoning:* No vendor publishes a hit rate, but three independent teams built the same artifact, which is meaningful. Two genuine properties: it prunes an unbounded search over a large MCP surface into a small number of determinate next queries, and it makes the reasoning auditable ('the curve was a ramp, so I tested rollout exposure'). Sift's design adds the anti-vacuum property — eight named checks that each fire or do not, so 'nothing fired' is a reportable result rather than a hole an LLM fills with narrative. Adapt rather than adopt wholesale: the specific tables are vendor- and stack-specific and must be re-derived, and a table applied outside its domain is a confident wrong routing.
  - *Adopt:* adapt
- **Treating an empty query result, an unauthenticated MCP server or a missing tool as a negative finding**
  - *Verdict:* contradicted-by-evidence
  - *Reasoning:* Not contradicted by a benchmark but by documented mechanism across every backend in the environment, which is stronger for this purpose. PostHog's own skill states the correction three separate times in one file — I verified 'useful context, not a failure' on disk — which is itself evidence of how hard the behavior is to instill. Structural causes of emptiness are pervasive and documented: log retention shorter than event retention, zero-padded unset trace_ids, replay not enabled for those users, $app_version not auto-captured on web/server SDKs, Sentry suspect commits absent without in-app frames or correct code mappings, Cloudflare Workers Logs at 3-7 day retention with sampling. Add the harness reality that OAuth-gated servers (Sentry, Cloudflare, Stripe) can be entirely absent in headless runs. An agent that reads empty as clean produces a wrong diagnosis with a spurious ruled-out list attached.
  - *Adopt:* reject
- **Reporting a root-cause category or a ranked suspect component as if it were a root cause**
  - *Verdict:* contradicted-by-evidence
  - *Reasoning:* Conflating these inflates apparent reliability by roughly 2-7x. RCACopilot's frequently-cited 0.766 is accuracy at predicting an incident's root cause CATEGORY from incident-handler-curated diagnostic data — a classification task over a fixed label set, deployed at Microsoft for 4+ years. Free-form causal explanation on comparable systems measures 11.34% (OpenRCA, whose benchmark and RCA-agent design I verified in the repo) to 35-39% (Microsoft's real cloud incidents). RCAEval's best AC@1 of 0.67-0.69 is on INJECTED resource and network faults, and its harder code-level fault datasets have no reported baselines at all — that gap between 0.67 on synthetic and 0.11 on real is the size of the synthetic-to-real illusion. Adapt: category triage is legitimate as a triage label, never as the diagnosis.
  - *Adopt:* adapt
- **Accepting an upstream AI root-cause output (Sentry Seer, Datadog Bits, Rootly, incident.io) as the answer**
  - *Verdict:* popular-but-unsupported
  - *Reasoning:* Not one of these products publishes an accuracy metric, a confidence model, or an independent reproduction step. Seer's documented gating is an ML 'fixability score' plus hard triggers of at least 10 events and at most 14 days old — a heuristic for whether evidence is thick enough, not a verification. Datadog's Bits docs describe an 'autonomous AI agent that... forms hypotheses' without enumerating data sources or evaluation. Rootly claims 10x and incident.io claims 5x with testimonials only. Sentry's own skill supplies the correct handling, which I verified verbatim on disk: treat Seer's output as 'a hypothesis to verify against the repo, not gospel'. Adapt: consume as a hypothesis carrying a 'retrieved' provenance tag, never as a finding, and never let it raise confidence on its own.
  - *Adopt:* adapt
- **Bounding the investigation and treating runaway episode length as a live failure signal**
  - *Verdict:* plausible-unproven
  - *Reasoning:* Split verdict, and this is a distinction the dossier misses. The SIGNAL is well measured: failed trajectories run consistently longer than successful ones across three agent frameworks and two benchmarks (OpenHands 98.62 vs 54.05 steps, +82.5%; Prometheus +50.7%; SWE-agent +18.5% on Verified, same direction on Lite). But the INTERVENTION does not follow from it — that is a correlation, and the obvious confound is that hard tasks produce both long trajectories and failures. Nothing shows that truncating a long run improves the outcome; it may simply convert a slow failure into a fast one. Adopt the budget as a device for forcing a structured write-up of what was ruled out (which has independent value) rather than as a claimed accuracy intervention, and do not tell the agent that stopping early makes it more likely to be right.
  - *Adopt:* adapt
- **Five Whys run as a fixed five-slot causal chain**
  - *Verdict:* popular-but-unsupported
  - *Reasoning:* No measurement supports it for LLM diagnosis, and the critique from the resilience-engineering literature is argumentative but pointed and independently converged: Allspaw ('The Infinite Hows') on single causal chains, first stories, hindsight bias and termination in blame; Cook's 'post-accident attribution to a root cause is fundamentally wrong'. The LLM-specific objection is sharper than either: a template with five labeled slots is a form-filling prompt, and form-filling prompts are exactly what induce fabrication of plausible intermediate links, each inheriting the credibility of the evidenced ones around it. prp-debug's version even pre-labels the fifth slot '[ROOT CAUSE]', asserting depth five before any investigation. It also cannot represent compound causes. Reject the fixed-depth template; keep the underlying contributing-causes framing.
  - *Adopt:* reject
- **The awesome-list debugger agent: 200-300 lines of technique-name bullets, Write/Edit granted, fabricated worked example, no reproduction gate and no inconclusive outcome**
  - *Verdict:* popular-but-unsupported
  - *Reasoning:* The dossier's mechanical check is the damning part and it is checkable: all six debug/incident/SRE agents in one popular collection are 286 lines with 176 bullets and 6 headings each, differing only by noun substitution — generated from a template, not authored from debugging experience. Worse than inert: the shipped 'delivery notification' example asserts a specific root cause plus a fabricated 15%-to-0% error-rate improvement with no evidence shown, and the progress object carries root_cause_found: true. Few-shot demonstrations are the strongest behavioral signal in a prompt, so this is a worked example of confident fabrication. Related instance: importing 'Fix first, understand later' from an SRE incident-commander agent into a diagnosis-only agent authorizes skipping investigation entirely.
  - *Adopt:* reject
- **Per-granularity confidence (subsystem / file / function / line) rather than one scalar for the whole diagnosis**
  - *Verdict:* battle-tested
  - *Reasoning:* Accuracy falls by an order of magnitude across granularity, so a single number necessarily overstates the specific claims and understates the general ones — which is precisely the shape of a persuasive wrong diagnosis. Agentless's funnel: 81.67% file-level, 58.33% element-level, ~50% edit-location, 32.00% actually resolved. The ICSE 2026 trajectory study: even among SUCCESSFUL patches, file-level match exceeds 90% but function-level is ~27% and exact-hunk 4-8.4%, with the authors concluding 'perfect fault localisation is neither necessary nor sufficient for success'. Corollary worth encoding: do not set exact line identification as the success bar, because demanding precision the agent does not have is a direct instruction to fabricate it.
  - *Adopt:* adopt
- **An evidence-admissibility list that explicitly bans generic technology explanation as proof**
  - *Verdict:* plausible-unproven
  - *Reasoning:* Unmeasured as a mechanism, but it targets a failure mode that IS measured and is the most common one. AutoFL's hand-audit of 300 explanations found the dominant category was not wrongness but vacuousness: 46.7% 'Bland' — describing the test and the covered code with no causal analysis — against 20% accurate and 26.3% containing at least one inaccurate statement. Both bland and imprecise output reads as competent. prp-debug's invalid-evidence row 'Explaining how technology works in general' names the exact tic: substituting a fluent, correct account of how JWTs or connection pools work for any observation about this system. Pair it with AutoFL's own rubric bar — the explanation must go beyond restating the error message — which doubles as a ready-made output contract with published base rates attached.
  - *Adopt:* adopt

## Convergent wisdom

- **Execution beats reading: a claim verified by running something outranks any claim derived from reading code or telemetry, and the agent should be pushed toward producing observations rather than interpretations**
  - *Independent sources:*
    - Agans Rule 2 'Make it fail' and Rule 3 'Quit thinking and look'
    - debug-gym (Microsoft Research), whose premise is that agents must interactively explore to gather task-relevant information rather than reason from static code
    - Anthropic's scored SWE-bench Lite config, which makes 'create a script to reproduce the error and execute it to confirm the error' step 2 of 5
    - SWT-Bench (NeurIPS 2024): generated reproduction tests roughly doubled SWE-Agent patch precision
    - prp-debug: 'Test, don't just read. Execution proves behavior; reading proves intent.'
    - harness-debugging: 'If you cannot reproduce the failure, you cannot debug it. Escalate.'
    - Chrome DevTools MCP framing of un-instrumented agents as 'programming with a blindfold on'
- **An empty or unavailable data source means 'not observed', never 'did not happen' — and the distinction between not-connected, not-instrumented and genuinely-absent must be stated**
  - *Independent sources:*
    - PostHog investigating-error-issue, which states the correction three separate times in one file (verified on disk at 1.1.49: 'useful context, not a failure')
    - Sentry suspect-commits docs, which enumerate four silence modes (no in-app frames, wrong code mappings, issue predates integration, error issues only)
    - Cloudflare Workers Logs retention limits (7 days paid / 3 days free) with auto-sampling past 5B logs/day
    - Zeller & Hildebrandt's UNRESOLVED as a formal third test outcome alongside PASS and FAIL
    - Google SRE Ch.12, which lists misinterpreting metrics among its named pitfalls
    - The deferred-tool harness itself: OAuth-gated MCP servers (Sentry, Cloudflare, Stripe) can be entirely absent in headless runs
- **The crash site is not the fault site; the interesting frame is upstream, at the last point where a value was still correct**
  - *Independent sources:*
    - AutoFL's difficulty categorization, in which a large plurality of Defects4J bugs have no faulty method in the stack trace or the failing test's direct callees
    - FALCON (ICSE 2025): the faulty method appears in both passing and failing logs while the innocent downstream callee appears only in the failing log
    - Sentry references/concepts/errors.md: the crash may be a downstream symptom of a different issue on the same trace (verified on disk)
    - Nelson Elhage's backward reasoning from an invariant violation by enumerating the complete set of writers
    - harness-debugging Step 6: trace backward until the actual value diverges from the expected value
    - prp-debug: 'Symptoms lie. The error message tells you what failed, not why.'
- **Temporal correlation with a change requires a confirmation artifact proving the change actually executed and actually contained the suspect code**
  - *Independent sources:*
    - PostHog checking-deploy-timing (verified verbatim on disk): 'A later date_marker is necessary but not sufficient', with the gh api compare check requiring behind_by:0
    - CockroachDB drt-analyze Phase 4: search for operation confirmation logs to verify the operation actually caused the finding
    - Google SRE Ch.12, which names mistaking correlation for causation on 'spurious coincidences in complex systems'
    - wshobson parallel-debugging's evidence table, which rates 'error rate increased after commit abc123' as Correlational/Medium, below Direct
    - Sentry suspect commits, which derive from git blame on in-app frames rather than from timing
- **Curated, aggregated, skeletal evidence outperforms raw volume — the agent's job is evidence selection, and every retrieval is a budgeted choice**
  - *Independent sources:*
    - Agentless: skeleton input 58.33% at $0.02 versus complete-file input 53.67% at $0.15
    - OpenRCA's RCA-agent (verified in repo README): writes Python for retrieval and analysis so 'the model avoids processing overly long contexts'
    - Execution-trace repair study: naive trace injection helped in only 2 of 6 configurations, with benefit decreasing as complexity rose
    - Grafana MCP's get_dashboard_summary and get_dashboard_property, which exist explicitly to reduce token consumption
    - Rootly MCP's selectable ~70-tool slim profile and Code Mode endpoint
    - PostHog exploring-apm-traces: persist large traces to file and run summary scripts rather than loading them
- **Diagnosis must be structurally separated from repair, and the separation should be enforced by capability rather than by instruction**
  - *Independent sources:*
    - boparaiamrit investigator.md: allowed-tools limited to Read/Grep/Glob/Bash plus 'You do NOT fix code'
    - wshobson team-debugger.md: tools list omits Write and Edit
    - harness-debugging: 'Investigation phases are read-only... If you find yourself writing a fix during investigation, you have skipped ahead.'
    - PostHog investigating-error-issue (verified on disk): 'Don't propose a fix in the synthesis unless the cause is obvious from the sample stack. Hypotheses backed by data are more useful than confident guesses.'

- **The output schema must contain a counted, reasoned 'undetermined' value, because a schema with no shape for it guarantees the root-cause field gets filled regardless**
  - *Independent sources:*
    - Microsoft RCA agent study: 'Insufficient Evidence' emitted in 66% of incorrect predictions
    - GitLens investigate skill: report header counts 'Issues inconclusive: N', with Inconclusive and Insufficient Information as peers of Confirmed Bug

- **Constrain the candidate set with cheap structural or statistical signal before spending model tokens, so the model verifies rather than searches**
  - *Independent sources:*

  - *Independent sources:*

## Cargo cult

- **'Check the logs, check the metrics, check recent changes, check the stack trace' presented as an investigation procedure**
  - *Why suspect:* Names no tool, no query, no schema, no ordering rule, and no handling for an empty or unavailable result. Nothing in it changes what the model does at any branch point, so behavior falls back entirely to base priors — which is the confident-plausible-narrative failure this agent exists to avoid. Contrast the artifacts that actually encode decisions: PostHog's skill names the exact tool, the exact HogQL, and what an empty result means; CockroachDB's table maps 25 finding types to specific metrics and log search terms.
- **Model-generated numeric confidence scores and per-hypothesis probability percentages ('85% confident', 'Hypothesis A: 0.6')**
  - *Why suspect:* Directly contradicted, and I verified the source text: ECE 'ranging from 0.09 to 0.73, suggesting intrinsic LLM confidences are poor predictors of code correctness', with only 52% of >90%-confidence completions passing tests and a buggy completion rated 91%. The number is decoration in the syntax of precision, which is strictly worse than no number because it launders a wrong diagnosis into an actionable-looking one. Any confidence expression must be a count of external corroborations, not an introspective estimate.
- **Five Whys with five literal WHY/BECAUSE slots, especially with the fifth pre-labeled '[ROOT CAUSE]'**
  - *Why suspect:* Real causal chains are frequently two links deep or branch into several jointly-sufficient contributing causes. A fixed-depth template is a form-filling prompt, and it invites fabrication of plausible intermediate links, each inheriting the credibility of the evidenced ones beside it. Pre-labeling the terminal slot asserts the chain's depth before any investigation has occurred, and the structure cannot represent compound causes at all.
- **Severity and priority labels (P0/P1, critical/high/medium) attached with no stated criteria**
  - *Why suspect:* With no rubric binding the label to observable quantities (fraction of users affected, revenue path, data loss, reversibility), the label is a mood. It is also load-bearing in a way a mood should not be, because humans triage from it. If severity is emitted at all it must be derived from a blast-radius measurement the agent actually ran, and it should be omitted when that measurement failed.
- **Technique name-dropping: 'rubber duck debugging', 'time travel debugging', 'statistical debugging', 'binary search', 'hypothesis formation' as bullet lists**
  - *Why suspect:* Noun phrases with no procedure attached. 'Binary search' without a bisection oracle and an exit-code contract is not an instruction; 'rubber duck debugging' is not an action an agent can take at all. The mechanical tell that these are generated rather than authored: six debug/incident/SRE agents in one popular collection are each 286 lines with 176 bullets and 6 headings, differing only by noun substitution.
- **Vendor name lists as capability: 'Error tracking (Sentry, Rollbar, Bugsnag), APM (Datadog, New Relic, Dynatrace), Traces (Jaeger, Zipkin, Honeycomb)'**
  - *Why suspect:* Names no tool call, no query language, no auth state and no absent-source fallback. In a deferred-schema harness this is actively harmful: it primes the agent to believe capabilities exist, to call tools whose schemas were never loaded (InputValidationError), or to narrate what a query would have returned. It also encourages reading an unauthenticated server as a clean bill of health.
- **Worked examples containing fabricated metrics ('reduced error rate from 15% to 0%', 'latency reduced 70%', 'query count: 15 to 1', 'root_cause_found: true')**
  - *Why suspect:* Few-shot demonstrations are the strongest behavioral signal in a prompt, and these demonstrate asserting a specific root cause plus quantified impact with no evidence shown. This is a template for confident fabrication sitting inside the artifact that is supposed to prevent it. If an example is included at all, it should be one where the agent returns inconclusive and says what it would need next.
- **'Fix first, understand later' imported into a diagnosis-only agent**
  - *Why suspect:* Correct doctrine for a human incident commander holding a rollback button; exactly wrong for an agent whose sole deliverable is a causal claim. Copied unmodified it authorizes skipping investigation and proposing mitigations grounded in nothing. The source file containing it also contains its own refutation two bullets earlier ('a wrong fix can exponentially worsen the situation'), which is a good demonstration of why these artifacts must be read rather than inherited.
- **A 'now critique your own reasoning' or 'double-check your diagnosis' reflection step with no new evidence gathered in between**
  - *Why suspect:* Contradicted by Huang et al. (ICLR 2024) on intrinsic self-correction degrading performance, and by the ICSE 2025 finding that reflective confidence methods are 'rather inconsistent'. With no new observation the second pass can only re-weight the same context, and the reliable effect is converting a hedged answer into a confidently defended one — the opposite of the intent.
- **'Investigate thoroughly', 'be systematic', 'think step by step', 'consider all possibilities' as investigation instructions**
  - *Why suspect:* Unbounded exhortation against a large MCP surface produces wandering and budget exhaustion before convergence, and it gives the agent no way to know it has left the protocol. It also cuts against the measured direction of travel: longer trajectories correlate with failure across three agent frameworks, and curated evidence beats bulk evidence. Replace with routing tables and decision rules that make the next query determinate.
- **A report template with exactly one root_cause field**
  - *Why suspect:* Single-cause framing is usually wrong in any system with more than one component (Allspaw's 'each necessary but only jointly sufficient'; Cook's 'there is no isolated cause of an accident'), and a one-slot schema forces the agent to pick one contributing cause and silently drop the others. The schema shape determines the answer shape: if compound causes cannot be expressed, they will not be reported.
- **Success criteria with no inconclusive exit (e.g. ROOT_CAUSE_FOUND / EVIDENCE_CHAIN_COMPLETE / FIX_ACTIONABLE)**
  - *Why suspect:* A rubric with no failure state is an instruction to produce a root cause regardless of evidence. It is especially corrosive when it sits alongside a good rule like 'no evidence = no claim', because the model resolves the contradiction the cheap way — by finding something to put in the field. The measured base rates (11.34% on OpenRCA, 35-39% on real cloud incidents) mean undetermined is the majority outcome, so it must be a passing state.
- **Self-reported hit rates used as justification ('the USE method solves about 80% of server issues with 5% of the effort')**
  - *Why suspect:* Uncontrolled practitioner self-report with no measurement behind it, repeated widely enough to read as established. The underlying checklist has genuine value (a complete resource sweep, and 'nothing fired' as a reportable result), but the number should never be cited as evidence and should not be used to justify running the sweep ahead of cheaper discriminating experiments.
- **Citing very recent single preprints as settled benchmark evidence**
  - *Why suspect:* A provenance failure I found in the research itself: ORACLE-SWE (the source of the headline +52-point reproduction result) was labeled 'peer-reviewed-or-benchmarked', but on checking, it is explicitly still under peer review — an unreplicated preprint whose signals are oracle upper bounds extracted from gold patches and therefore unobtainable in the wild. Separately, the cited PostHog skill paths all reference version 1.1.54 while 1.1.49 is what is installed (the quoted content does verify at 1.1.49, and one claimed quote did not match at all). Neither error changes the conclusions here, but a design that leans on a single fresh number rather than on convergence inherits its retraction risk.

## Evidence mechanisms

- **Demonstrated causal control as the only route to the top confidence tier: the symptom must be shown to switch off when the suspected cause is removed and back on when it is restored**
  - *Evidence:* This is the strongest lever available, and its strength is structural rather than benchmarked — I want to be explicit about that rather than dress it up. A both-directions result is the one claim in a diagnosis an LLM cannot generate from priors: a stack trace, a metric chart and a causal chain can all be narrated fluently, but a toggle-off/toggle-on observation has to be produced by the environment. Supporting measured work: Zeller & Hildebrandt's 1-minimality (IEEE TSE 2002) is exactly this test at input granularity, achieving 90%+ reductions on real Mozilla and GCC failures; git bisect is it mechanized over history. Independently required by Agans Rule 9, prp-debug's necessity/sufficiency triad, and harness-debugging. No study A/Bs it as a prompt mechanism, and it is unavailable for many production incidents — so it gates the top tier rather than gating the report.
  - *Prompt implementation:* Make it a typed field, not a tone: causal_test: {cause_removed: symptom_gone | symptom_persisted | not_attempted | not_possible, cause_restored: symptom_returned | symptom_absent | not_attempted}. Hard rule: confidence PROVEN is unreachable unless both directions are populated with an observation the agent actually made. When not_possible, require a one-line reason (mitigated before capture, non-reproducible, no safe toggle) and cap at CONSISTENT. Add the counterfactual self-check from prp-debug: 'If I changed THIS, would the issue be prevented?' — if the agent's own answer is 'maybe' or 'partially', that hedge is the signal to keep going, not to publish at medium confidence.
- **Reproduction as a gate with a defined failure branch, plus a validity check on the reproduction itself**
  - *Evidence:* Convergent and partly measured. SWT-Bench (NeurIPS 2024) reports generated reproduction tests roughly doubled SWE-Agent patch precision; Anthropic's scored SWE-bench Lite config makes reproduction step 2 of 5; harness-debugging, investigator.md and prp-debug independently gate on it. But Agentless supplies the essential counterweight: of 300 issues, 213 generated tests emitted 'issue reproduced' against the broken repo while only 94 correctly emitted 'issues resolved' after the ground-truth patch — roughly 56% of apparent reproductions are invalid as oracles. Note also that the widely-cited +52-point figure comes from a preprint still under review, so do not rest the mechanism on it.
  - *Prompt implementation:* Two gates. (1) Reproduction is attempted before hypotheses are written; if it fails, the first line of the report says so and every hypothesis is capped at SUSPECTED — no exceptions, since without an oracle there is no experiment that could have falsified anything. (2) The repro must assert on the specific reported failure signature, not merely fail; and it must print a terminal sentinel ('script completed, no errors') so that silence is never read as success. For intermittent failures, record the rate (1 in 3? 1 in 10?) rather than accepting 'sometimes' — a rate is what makes a later fix verifiable.
- **Cross-run agreement as the confidence quantity, wholly replacing self-reported confidence**
  - *Evidence:* The best-measured calibration mechanism in the corpus, and I verified the table directly in the AutoFL PDF: Spearman +0.57 / +0.67 / +0.70 against Precision@1, Reciprocal Rank and Average Precision on Defects4J, and +0.52 / +0.50 / +0.49 on BugsInPy, all p<0.0001, across 798 bugs with 5 reruns. The complementary measurement is why one run is not enough: only ~20% of individual explanations were accurate, but 56.7% of bugs had at least one accurate explanation in the ensemble — single-shot answering throws away information demonstrably present. Cost is modest (AutoFL reports 87.24s per bug for all 5 runs). The alternative is dead on arrival: intrinsic confidence ECE 0.09-0.73, and only 52% of >90%-confidence completions pass tests.
  - *Prompt implementation:* Run N=3 independent passes with separate contexts and genuinely different entry points (different failing test, different symptom, different starting signal — not the same prompt re-rolled at temperature). Report agreement as a fraction of runs, never as a probability: 'named by 3/3 runs' or '2/3 runs, third named X instead'. Keep the disagreeing hypothesis in the report as a live alternative rather than discarding it. Say plainly in the prompt that agreement is a moderate ranking signal (rho 0.5-0.7), so 3/3 raises confidence one tier and never certifies correctness.
- **A first-class, counted 'insufficient evidence' outcome with a required reason, plus an explicit license to use it**
  - *Evidence:* One of very few mechanisms with a direct behavioral measurement: the Microsoft grounded RCA agent emitted 'Insufficient Evidence' in 66% of its incorrect predictions — most of the time it was wrong, it had already flagged that it lacked grounds — while its hallucination rate within incorrect predictions was 6% against 49% for the ungrounded retrieval baseline. Base rates make abstention the majority-adjacent outcome, not an edge case: 11.34% on OpenRCA's 335 real enterprise failures, 35-39% on real Microsoft cloud incidents, and even RCAEval's best AC@1 of 0.67-0.69 is on injected synthetic faults. Independently converged on by GitLens (counted in the report header) and CockroachDB (inconclusive branch emits a scoped debug.zip command).
  - *Prompt implementation:* Put it in the schema, not the prose: outcome ∈ {diagnosed, partially_diagnosed, insufficient_evidence, cannot_reproduce, likely_already_fixed}, with insufficient_evidence requiring a reason from a closed list and a 'what I would need next' field. State the base rate in the prompt as the reason confidence defaults low. Add the explicit license verbatim, because the default behavior is to produce an answer: 'It is perfectly acceptable to report investigation inconclusive. Do not force a conclusion.' Terminate inconclusive reports with a concrete next command, so abstention still ships something actionable.
- **Provenance tag on every claim: observed-in-tool-output, retrieved-from-existing-writeup, or inferred**
  - *Evidence:* The failure it intercepts is measured repeatedly. Cursor's sealed-environment study: 63% of one frontier model's successes retrieved the fix rather than derived it (57% upstream PR/file lookup, 9% git-history mining), with 7.5-20.7 point drops once git history and network were sealed. SWE-Bench+: 32.67% of successful patches had the solution stated in the issue or comments. SWE-Bench Illusion: 76% buggy-path identification on benchmark repos versus 53% on non-benchmark repos from issue text alone. In a live incident there is no upstream PR to find, so an untagged retrieved answer is a capability that evaporates exactly when needed. GitLens's Source Attribution is the cleanest implementation and it is a typed field in both its markdown and JSON output.
  - *Prompt implementation:* Every evidence bullet carries a tag. Add a report-level source_attribution ∈ {independent_analysis, confirmed_reporter_diagnosis, mixed} with the honest framing: 'The issue already contained file paths or a proposed cause; the investigation verified these claims but did not independently discover the cause.' Enforce that a claim tagged retrieved cannot on its own raise confidence above CONSISTENT — it must be independently reproduced or corroborated first. This also defuses the case where a bug report arrives with the reporter's guess attached and the agent hands it back as a finding.
- **Structured disambiguation of every empty result into not-connected / not-instrumented / genuinely-absent, with only real returns permitted to support a ruled-out claim**
  - *Evidence:* Highest-leverage guard in a multi-MCP environment, and supported by documented mechanism rather than one study. PostHog's own skill states the correction three separate times in a single file (I verified 'useful context, not a failure' on disk), which is itself evidence of how hard the behavior is to instill. Documented emptiness causes are pervasive: log retention shorter than event retention, zero-padded unset trace_ids, replay not enabled, $app_version not auto-captured on web/server SDKs, Sentry suspect commits requiring in-app frames plus correct code mappings, Cloudflare Workers Logs at 3-7 days with sampling past 5B/day. Add the harness fact that OAuth-gated servers can be entirely absent in headless runs, and that a truncated or timed-out query is indistinguishable from an empty one.
  - *Prompt implementation:* Require a sources_consulted table in every report: source | status ∈ {returned_data, returned_empty, unavailable_unauthenticated, not_attempted} | what_this_limits. Hard rule: only returned_data may support a 'ruled out' claim; returned_empty and unavailable downgrade every hypothesis that source would have tested and must be named in the output. Probe each source with one cheap availability call before building a plan around it, and load deferred tool schemas before planning any step that depends on them. Treat 'OAuth not completed' as an expected state with a stated fallback, not an error to retry.
- **Mandatory negative control: no dimension may be called implicated until the same breakdown has been run against the unaffected or overall population**
  - *Evidence:* Verified verbatim on disk in PostHog's APM skill: 'A value at 95% of errors but 10% of traffic is the culprit; one at 95% of both is just volume.' Independently automated by Honeycomb's BubbleUp and independently required by PostHog's feature-flag test (compare variant split among errors to overall exposure on the same flag in the same window). The cost of skipping it is measured elsewhere: FALCON shows every one of 34 spectrum-based formulas ranking the innocent downstream method first, because it appeared only in the failing run while the true fault appeared in both. This is base-rate correction — mathematically sound, one extra query, and it defeats the highest-frequency wrong-diagnosis generator in telemetry work.
  - *Prompt implementation:* Any breakdown finding must be reported as two numbers, share-among-affected and share-among-baseline, or it is inadmissible. Add the explicit counter-instinct: 'The thing unique to the failing run is usually downstream of the fault. Before indicting it, test the alternative that the culprit appears in BOTH populations and is merely behaving differently.' Extend the same rule to blast radius — require the agent to state the largest population NOT affected, since a cause that would have broken everyone is refuted by the unaffected set at near-zero cost.
- **Confirmation artifact required before any temporal correlation is promoted above 'correlational'**
  - *Evidence:* Two vendors independently ship the refutation of the most seductive cheap finding in incident response. PostHog checking-deploy-timing, verified verbatim on disk: 'A later date_marker is necessary but not sufficient — a deploy can fire just after the merge yet build a slightly older commit', with the exact check gh api repos/<org>/<repo>/compare/<merge_sha>...<deployed_sha> --jq '{status,ahead_by,behind_by}' requiring behind_by:0. CockroachDB independently requires searching for operation-confirmation logs to 'verify the operation actually caused the finding'. Google SRE names spurious coincidences in complex systems as a listed pitfall. PostHog adds the read-path trap: a code change that alters querying applies retroactively to all historical data and moves no volume at all.
  - *Prompt implementation:* change_correlation requires a confirmation_artifact field — git ancestry compare output, a deploy log line, a flag-evaluation record — or the finding is emitted as correlational and cannot be the reported cause. Ban answering 'when did this ship' from event volume or dashboard inflections; require deploy markers. Set an explicit default-window rule too, since PostHog warns that default query ranges silently truncate the original first_seen event, producing a wrong onset date that then anchors the entire deploy analysis on the wrong release.
- **Capability-level enforcement of diagnose-don't-fix via the tool allowlist**
  - *Evidence:* Convergent across three independent artifacts (investigator.md restricts to Read/Grep/Glob/Bash with 'You do NOT fix code'; team-debugger omits Write and Edit; harness-debugging makes investigation phases read-only), plus PostHog's own guidance verified on disk ('Don't propose a fix in the synthesis unless the cause is obvious... Hypotheses backed by data are more useful than confident guesses'). Two mechanisms rather than one: a prose constraint competes with strong helpfulness priors at exactly the moment the agent believes it has the answer, whereas a missing tool does not; and once a fix is written the agent is invested in the hypothesis that motivated it, so subsequent evidence is read as confirmation. Independently, practitioners report write-enabled observability agents silencing real alerts and re-triggering failed deploys during outages.
  - *Prompt implementation:* Omit Edit and Write from the allowlist entirely. Restrict MCP surface to read tools and name the write tools that sit adjacent to them as forbidden (error-tracking issue update/merge, execute_write_query, browser_run_code_unsafe). Add the symptom-suppression detector for any mitigation the agent does suggest: a try/catch that swallows, a retry loop, an added delay, a widened type, or a special case for the failing input all mean the cause was not found, and must be labeled as suppression rather than resolution.
- **Separate confidence per granularity — subsystem, file, function, line — rather than one scalar**
  - *Evidence:* Accuracy falls by an order of magnitude as granularity tightens, so any single number is necessarily wrong in one direction. Agentless's funnel: 81.67% file-level, 58.33% element-level, ~50% edit-location, 32.00% resolved. The ICSE 2026 trajectory study measures the same shape among successful patches: >90% file, ~27% function, 4-8.4% exact hunk, with the authors concluding 'perfect fault localisation is neither necessary nor sufficient for success'. A single scalar overstates the line claim and understates a genuinely useful subsystem claim — which is exactly the shape of a persuasive wrong diagnosis.
  - *Prompt implementation:* Emit a confidence tier per granularity and allow them to differ sharply ('subsystem: strong; file: consistent; line: speculative'). Explicitly do NOT set exact line identification as the success bar — demanding precision the agent does not have is a direct instruction to fabricate it. Bind each tier to mechanical criteria borrowed from CockroachDB rather than to feeling: low = single signal, could be coincidence or noise; moderate = 2+ independent signal types agreeing; high = metric plus log plus timeline all converge; proven = the both-directions causal test passed.
- **Falsifier pre-committed per hypothesis, written before any evidence is gathered for it**
  - *Evidence:* Unmeasured for LLM diagnosis — I want to be clear that no A/B exists — but structurally sound and convergently adopted (wshobson's hypothesis template, CockroachDB's 'WHAT WOULD CONFIRM/DENY THIS' field, GitLens's alternatives-ruled-out section, harness-debugging). The ordering constraint is what does the work: a falsifier written after the fact is chosen to be one that happens not to have been met, which is unfalsifiable by construction. The failure it targets is measured in an adjacent field — premature closure and anchoring are the identified top cognitive causes of diagnostic error in medicine, where diagnostic error accounted for 17% of preventable errors in the Harvard Medical Practice Study.
  - *Prompt implementation:* The hypothesis object requires falsifying_observation populated before any tool call is made in service of that hypothesis. Carry 2-3 live hypotheses, not one and not seven. Add the third evidence verdict most prompts omit — AMBIGUOUS (consistent with more than one hypothesis) — and forbid counting ambiguous evidence as confirming, since that is the main mechanism by which a wrong narrative accumulates apparent support. Report falsified hypotheses as findings in a first-class 'ruled out' section: negative results are the part of the report a human can actually verify.
- **An inadmissible-evidence list that specifically names generic technology explanation, plus an output bar that excludes restating the error**
  - *Evidence:* Targets the measured dominant failure, which is vacuousness rather than wrongness. AutoFL's hand-audit of 300 explanations, which I verified in the paper: 20% Accurate, 26.3% Imprecise (at least one inaccurate statement), and 46.7% 'Bland' — describing the test and the covered code with no causal analysis at all. Bland output reads as competent work. prp-debug's invalid-evidence row names the exact tic: 'Explaining how technology works in general' — a fluent, correct account of how JWTs or connection pools or React reconciliation work, containing zero observations about this system.
  - *Prompt implementation:* Ship the admissibility table. Valid: file:line with the actual snippet; output of a command actually run; a test actually executed. Invalid: 'likely', 'probably', 'may'; logical deduction with no code proof; general explanation of how the technology works. Set the output bar using AutoFL's own audit rubric, which doubles as a contract with published base rates: the explanation must describe why the failing state arose and go beyond explaining the error message. Add the version-drift rule as a special case — look up current library behavior via Context7 rather than asserting an API contract from memory, since remembered semantics are a top source of confidently wrong 'it worked yesterday' diagnoses.
- **Backward trace terminating on value divergence, with the complete set of writers enumerated**
  - *Evidence:* Replaces the stack-trace-scoped search that the data contradicts: in AutoFL's categorization a large plurality of Defects4J bugs have no faulty method in the stack trace or the failing test's direct callees, and Sentry's own errors doc (verified on disk) warns the crash may be a downstream symptom of a different issue on the same trace. The specific technique converges independently: Elhage's enumerate-the-writers ('if this field is NULL, someone set it; the only code that sets it is here, here, here'), harness-debugging's 'continue until you find where the actual value diverges from the expected value', and Google SRE's simplify-and-reduce with known inputs at each boundary. Its virtue is producing a closed, checkable candidate set instead of an open-ended narrative.
  - *Prompt implementation:* Require three named outputs before any hypothesis: the invariant that was violated, the frame at which it was last known to hold, and the enumerated complete set of code paths that could have violated it. Terminate the trace on value divergence, not on a frame count. Instruct reading each function in the chain completely rather than inferring behavior from its name. Add the symmetric checks: verify the issue is ONE bug before diagnosing it (compare earliest and most recent occurrence; materially different stack roots mean a grouping mistake, and any single cause will be wrong for most of the volume), and verify the code still exists at the release revision on the event rather than on main — if the frames are absent from the repo, stop and flag rather than reasoning around it.
